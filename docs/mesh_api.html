Mesh

class meshtool.Mesh[source]

Mesh representation based on the meshio.Mesh object. Quad elements are not supported.

Build a mesh with from_file() or from_arrays().

node_coords

Node coordinates. z is filled with 0 if the input points are 2D.

Type:

(nn, 3) ndarray

x, y, z

Views of the columns of node_coords.

Type:

(nn,) ndarray

nn, nc, ne

Number of nodes, triangle and line cells.

Type:

int

connectivity

0-based node indices of each triangle.

Type:

(nc, 3) ndarray

edge_nodes

0-based node indices of each line cell (empty if there is none).

Type:

(ne, 2) ndarray

physical_names

Mapping from physical group name to the list of its (dim, tag) pairs, as read from the $PhysicalNames section of the file. A name shared by several physical groups maps to several pairs. Empty if the section is absent.

Type:

dict[str, list[tuple[int, int]]]

metadata

Custom Gmsh blocks, preserved when writing a .msh file.

Type:

dict[str, str]

meshio_mesh

Underlying mesh object.

Type:

meshio.Mesh

Notes

Geometry depends on the CRS. With a geographic CRS (lon/lat in degrees), areas and perimeters are computed on the sphere from 3D coordinates, while point location and interpolation are done in the (lon, lat) plane. With a projected CRS or crs=None, everything is planar, in the units of the coordinates: areas are then true m² only if the projection preserves distances.

The antimeridian is not handled: a mesh crossing it is not supported.
